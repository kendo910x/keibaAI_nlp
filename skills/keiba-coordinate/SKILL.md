# 親の進行と引き渡し

競馬の自然言語を広く、大量に、継続して蓄積する。分類・収集は9割がた役立てば十分。曖昧な日時・対象、少数の誤りを許容し、全件検査や精密な正解率測定を条件にしない。この方針と探索の裁量を子の依頼と次の親への引き継ぎにも書く。

JSTの開催を確かめ、次週末の事前、前週末の事後、数年前の発掘のいずれかを選ぶ。一覧がよく増える時は媒体と期間、登録から出馬表へ進む時は未探索馬のまとまり、特集が充実していれば競走を作業単位にする。競走は分かっている開催日・競馬場・R番号と名称で渡し、回次は資料で確認できる場合に添える。子へ任せる場合は `delegate_task` を使い、順番、深掘り、再訪と終了を親が選ぶ。注目レースだけに偏れば一般競走や過去馬にも順番を渡す。

主要媒体の基礎調査が不足していれば、広い検索で競馬ポータル・大手スポーツ紙を発見し、一覧と本文を読む作業を配分する。一媒体の収集件数や子の正常終了だけで研究完了としない。記事が見つからない馬へ際限なく追加探索を要求しない。初期データの専用Local LLM処理は数日〜1週間程度でもよく、処理速度を独自の合格条件にしない。

過去の勝ち馬・出走馬を背景に添えるときは、既知の談話や結果の参照先を使う。今回の2021年ジャパンCでは、親が書き足した勝ち馬を子が保存済み談話で訂正できた。引き継ぎには、取材や調教の実施日と記事に表示された掲載日を分けて書く。月日が分からなければ、手掛かりの馬名と取得IDだけでも次へ渡せる。

子には目的、対象年・開催、既知の版や検索語、残った問い、`keiba-search` の名前、作業範囲を含める。子は独立した状態で始まるため「さっきの馬」のような参照は実名やIDに置き換える。親に表示されたAGENTS.mdは標準子の初期文脈には入らない。今回の研究プロファイルでは、子に検索Skillと、その `references/work-rules.md` を `skill_view` で開くよう伝える。別の配置では子が実際に読める場所を指定する。検索・取得・分類は研究用MCP、改善は研究用Skillの中で行う。

研究プロファイルへ複製した規約は最新版を使う。2026-11-26の独自robots事前拒否の撤廃と、Local LLM処理時間の許容も子へ渡し、古い `work-rules.md` から旧条件を復活させない。

ブラウザーのない研究VMには、日付を選んだPC画面の候補と次のoffsetを渡せる。別の日・馬からの発見を確かめるときは対象だけを渡し、検索Skillを開いて静的な月別一覧等を本人に探させる。保存した掲載先・配信元、記事の版、再利用か新規かをそれぞれ照合する。

本文をコードで直接保存し、未解釈の取得IDを次へ渡す。次の入口を選ぶには見出しや `excerpt` で足りる場合もある。`interpret` は分類Skillと一記事の本文だけで独立推論する。読解や分類の再試行を待つ間も別の一覧の保存を進められる。親には名簿の段階、掲載日または活動年、一覧ID・次のoffset、残った問いを返す。

子の返事は次の担当が使える長さにする。例は「対象と時点／検索・取得・解釈のID／分かったこと／未探索・取得不可・再訪先」。raw本文や思考の転載は不要。子の終了理由と保存済みIDを確認し、途中終了は残った工程から渡す。ほかの馬にまで一律に拡張しない。適用場面のある知見は `skill_manage` で研究用Skillに小さく追記してよい。次の子には同じSkillを開き直させ、観察した使い道を返してもらう。以前の版はGitや研究用スナップショットから参照できる。
