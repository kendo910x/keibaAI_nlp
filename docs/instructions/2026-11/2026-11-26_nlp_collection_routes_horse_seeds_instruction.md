# KeibaAI NLP — 記事への到達経路と馬名を起点にした収集研究

作成日: 2026-11-26（JST）  
担当: Codex（実地研究・必要な補助実装・Skillへの反映）  
確認したNLP基準版: `edac9a1c65422748e95b71c199c26699862d2611`

## 0. 今回の目的と、維持する方針

**Codex自身が、どのサイトのどの入口をどう辿れば競馬記事を広く集められるかを研究する。媒体の一覧・特集・サイト内検索と、登録馬・出走馬・過去の出走馬の名簿を組み合わせ、記事が継続して増える方法を作る。**

本書は、[初回指示書][initial]に対する実施結果と、その後のユーザーの指摘・合意を反映する続行指示である。今回の研究の目的・手順・終了の考え方は本書を優先する。[初回レポート][report]の原文保存・独立推論・Hermes試用の成果は再利用するが、記事発見・収集方法の研究は続行する。

自然言語の曖昧さを許容し、分類・収集は**「9割がた当たれば十分」**という実用性の目安を維持する。これは90%の達成証明や受入試験ではない。少数の誤分類・取りこぼし・表現の粗さを許容し、日時・対象・有用性・信頼性が不確かでも情報を残す。全件検査、全頭の外部ID照合、精密な時点証明を条件にしない。後続のコード相談や引き継ぎで独自に厳格化しない。

**意味の完全性を求めないことと、探索を少数の成功例で終えることは別である。** 今回は収集量と到達範囲を広げる研究を行う。取得可能な記事が多数ある入口を見つけたら、数件の精読で止めず、一覧や候補群から実際に本文をまとめて保存するところまで試す。

## 1. 前回から変える点

[初回レポート][report]ではCodexが17回、Hermesが8回検索し、全体で148候補URLから25 URLの本文を保存した。3つのSkillと親子Hermesの試用には成果がある。一方、サイト内の一覧・ページ送り・馬別のニュース等を使って収集を広げる実践知は不足している。

[研究用補助コード][code]は検索結果の上位候補を `capture(search_id, rank)` で選ぶ構成で、サイト内で見つけたURLを直接扱う経路や軽い本文・リンク閲覧がない。記事解釈待ちで次の検索が止まったことも報告されている。Codexの研究を、この現在のツール構成に閉じ込めない。

- Codex自身が検索・サイト閲覧・一覧の探索・本文確認を行う。Hermesの試行結果を待って研究を進める構成にしない。
- ニュース一覧、カテゴリ、日付別一覧、レース特集、サイト内検索、ページ送り、馬別ページ、関連記事・連載等を実際に辿る。
- 日常運用でも馬名一覧を主要な探索の入口とする。週初は特別登録馬など、出馬表公表後は一般競走を含む出走馬、事後は実際の出走馬を使う。
- 過去記事は、v3の過去10年間の出走履歴から得た馬名一覧を有力な入口とする。重賞名・有名馬だけに対象を限定しない。
- 本文保存と重い記事解釈を分け、未解釈の記事を蓄積しながら探索を進める。
- 研究成果を既存Skillへ反映し、その後にHermesで使えるかを試す。親子の正常終了やSkillのファイル数を研究の中心成果にしない。

## 2. 媒体の入口と馬名一覧を併用する

媒体側から記事を拾う方法と、馬側から記事を探す方法を併用する。レース名検索も引き続き利用できる。方法・順序・配分・切替はCodexが判断する。

| 場面 | 馬名を得る入口 | 主な探索 |
|---|---|---|
| 日常・週初からの事前情報 | 公表された特別登録馬、取材記事等の出走予定馬 | 新着・特集の巡回と、登録馬・予定馬ごとの調教、状態、陣営談、前走からの経過の探索 |
| 日常・出馬表公表後の事前情報 | 一般競走を含む出馬表 | 新馬・未勝利・条件戦の馬も候補へ加え、既知の記事を再利用しながら未探索馬と新着へ広げる |
| 日常・レース後の情報 | 出馬表・結果から得た出走馬 | 当日談話、敗因、回顧、状態、次走等を、媒体一覧と馬名の両方から探す |
| 初期コーパス・数年前の記事 | 過去10年間に出走歴のある馬名と活動年 | 馬名、活動年、媒体内検索、過去の一覧・関連記事から当時の事前・事後資料を探す |

### 2.1 日常運用の馬名一覧

2026-11-26に確認したJRAの通常日程では、特別競走は原則1週前、GIは原則2週前の日曜日に特別登録を行う。一般競走を含む出馬表は通常木曜16時すぎに馬番・枠番なしで発表され、通常はレース前日10時すぎに馬番・枠番付きとなる。GI・変則開催等には例外がある。[特別登録の説明][jra-registration]・[出馬表の発表時刻][jra-entries]

したがって、週初から全競走の確定出走馬が分かるとは置かず、まず公表済みの登録馬・予定馬から始め、出馬表公表後に対象を補充する。**馬名による記事探索は枠順確定を待たなくてよい。** 公表時刻を厳密に監視する基盤や、本書の日程を固定した自動実行を先に作る必要はない。

既存v3や利用可能な公式資料から、どの段階の一覧を取得できるかを実際に確認する。「公開サイトに出た」と「既存DBへ取り込まれた」は区別する。現行Liveが当日朝に使う一覧を、そのまま週初にも存在すると仮定しない。既存経路で早期一覧を得られなければ、公開ページの取得や研究用の一方向エクスポートで補えるか調べる。

一覧が増えたら未探索の馬を加え、既に探した馬も新しい記事が出る時期には再訪する。同じ馬が複数競走に登録されていても、同じ記事の取得を無意味に繰り返さない。登録後の回避・除外・取消が分かっても、取得済みの記事は残す。登録・予定・出走の違いは分かる範囲で持てばよく、出走確定を収集条件にしない。

### 2.2 過去10年間の馬名一覧

v3の現在の現役馬一覧ではなく、対象期間の出走履歴から候補を作る。期間の起終日を記録し、引退馬や条件戦を中心に走った馬も含める。過去10年分の候補一覧を用意することと、今回の研究で全馬の探索を完了することは分ける。

参照したv3版 `6b0f354fdec08ee281b0a9ec0420f40dd690392e` の `se_core` には、出走日 `SE_kaisai_ymd`、馬識別子 `SE12_blood_reg_no`、馬名 `SE13_uma_name` がある。[テーブル定義][v3-schema]。実行時は現行の正規のDB設定・スキーマを確認し、読み取り専用で馬名・活動年または期間・元の馬ID・対象区分程度を取り出す。実DBの頭数や期間充足はまだ測定していない。

この一覧は検索の手掛かりであり、NLPの保存時にv3との照合を必須にするものではない。v3の学習工程やCFSを起動せず、既存の読み取り専用参照またはエクスポートを使う。全馬の厳密な同定や、双方向同期の構築は不要である。

馬名だけでは成績表や最近の話題に偏る場合、活動年、当時の開催、過去走、調教師等を足す。サイト内の馬名検索・関連ニュース一覧も試す。全馬に同一の検索語セットや検索回数を強制せず、発見と行き詰まりに応じて変える。ある馬から見つかった記事に別の馬の情報があれば、そちらも蓄積する。

### 2.3 一覧を収集フィルタにしない

名簿にいない馬の記事、馬名がない馬場・コース・騎手・厩舎等の記事も残せるようにする。馬名一覧は探索を広げる入口であり、保存を許す対象の限定リストではない。今週出走する馬を調べて見つかった過去記事も蓄積し、記事中の話をすべて今週の競走へ強制的に結び付けない。

## 3. Codexが行う実地研究

### 3.1 サイトの構造を調べる

複数の媒体で、一覧や検索結果から記事へ辿り、次ページ・別の日・別の馬へ広げる。有効な入口、具体的な操作、返る記事の性質、再訪時の使い方を記録する。URLの規則は実際のリンクやページ表示で確認し、未確認の年・ページへ同じ規則が必ず通用すると断定しない。

レビューで確認した次の入口を着手候補として使える。固定ホワイトリストではなく、新しい媒体や個人の分析記事等も探索してよい。

| 入口 | 確認済みの手掛かり |
|---|---|
| [netkeibaニュース一覧](https://news.netkeiba.com/?pid=news_backnumber) | カテゴリと「記事から検索」。ジャパンカップのサイト内検索は次ページへ進め、最初の2ページで異なる40 URLを確認した。候補数であり、本文保存数ではない |
| netkeibaの馬名による記事検索 | タンタラスの検索から、[2021年の六甲アイランドS・3勝クラスの談話記事](https://news.netkeiba.com/?pid=news_view&no=197549)へ到達した。別の馬の騎手談も含まれていた |
| [スポニチ競馬Webニュース一覧](https://keiba.sponichi.co.jp/news/) | 日付・キーワードの検索欄。検索欄の存在確認と、入力して得られる範囲の検証は区別する |
| [スポニチの2026年ジャパンC一覧](https://keiba.sponichi.co.jp/feature/horseracing/G1/japanc/2026) | 馬別の調教・陣営談の記事リンクがまとまっており、一覧から記事本文へ到達できた |
| [日刊スポーツ競馬ニュース一覧](https://www.nikkansports.com/keiba/news/) | 日付ごとの見出しに、重賞の取材と条件戦馬の次走等が並ぶ。利用する取得経路で記事リンクまで得られるか確認する |

静的なテキスト取得で一覧やリンクが出なければ、公開ページの表示後の状態、利用可能なブラウザー、HTMLのリンク抽出等、正規に使える手段を検討する。単なる取得機能の不足を「記事がない」と扱わない。アクセス拒否や有料壁の回避は行わず、その入口の制約を記して別の利用可能な入口へ進む。

### 3.2 Codexの調査手段を狭めない

Codexが利用できる検索、ブラウザー、HTTP取得、小さな補助コード等を使ってよい。最初から共用Yahooの上位結果だけ、または既存Hermesの3ツールだけに限定しない。共用経路と別の経路で結果が違えば簡単に記録し、Hermesへ渡す際に必要な能力を整理する。製品の全面比較は不要である。

検索語、媒体、馬、期間、調査順、追加試行、切り上げはCodexの裁量とする。記事が多い一つのGIだけで結論にせず、一般競走や数年前の異なる馬にも広げ、方法がどこで役立つかを見る。日常の事前・事後・数年前の発掘は別々に整理するが、役立つ収集手段は共用する。

### 3.3 記事をまとめて保存し、量が増えるところまで試す

一覧・検索・記事内リンクから候補を取り出し、既知URLを照合しながら本文を保存する。取得・保存は通常コードが直接行う。日時や意味の曖昧さ、低い自信、平凡な内容を理由に厳しい事前選別をしない。明らかに無関係な画面等の扱いは裁量に任せる。

収集件数は一律に固定しない。ただし、記事が増える一覧や候補が残っているのに、各場面で数件見つかったことだけを研究終了の根拠にしない。複数ページ・複数日・複数の馬を実際に扱い、新しい本文が増える方法と、重複・取得困難・探索の手間が増える場合の切替を調べる。インターネット全体の網羅や、全候補の取得を要求するものではない。

記事の意味再構成を待たずに次の取得へ進む。探索方針に必要な本文や見出しはCodexがその場で読み、保存した全記事を直ちに独立推論へ通す必要はない。未解釈の本文から後で処理を続けられればよく、大規模なジョブ管理基盤は不要である。

## 4. 補助コード・Skill・Hermesへの反映

通常コードは、名簿の取込、一覧のURL抽出、ページ送りの反復、既知URLの照合、本文の取得・保存、簡単な再開位置の記録を支える。どの入口を使うか、どの馬・話題を深掘りするか、方法の切替や文章の解釈にはLLMの裁量を残す。

必要なら既存の研究用コードへ、発見したURLの直接取得、一覧・記事のリンク取得、軽い本文閲覧、複数候補の保存等を追加する。8,000字の取得上限やリンク消失が研究を妨げる場合は、研究用の許容された取得経路を改善してよい。共用サービスの恒久改修や最終DBの完成を先に要求しない。

研究で得た方法を[既存の検索Skill][search-skill]と、必要な分類・統括Skillへ反映する。サイトごとの入口と操作をreferencesへ分けるなど、構成は裁量に任せる。特定レースで効いた検索語の逸話だけでなく、一覧を辿る方法、馬名一覧の使い方、再訪・追加収集・再開方法を残す。配置や自己更新の仕組みは既存の成果を利用する。

親や子の作業単位をレース一つに固定しない。媒体×期間、馬のまとまり、レース特集等、実際に収集が進む単位を選ぶ。名簿からの機械的な候補作成と、LLMの探索判断を組み合わせる。

Codexによる方法の発見・収集を主作業とし、その成果がまとまった後でHermesへの移植を試す。代表的な媒体の導線や馬名一覧を実際に使えるかを確認する。途中で小さな移植確認をする裁量もあるが、毎回の方法比較を長時間の親子Hermes試行や全記事の独立推論へ置き換えない。既存のサブエージェント能力試験や一般的な長文性能試験を繰り返さない。

Skillの小さな改善に再承認や大規模な回帰試験を求めず、以前の版を参照できる形で更新する。意味の誤りが多発する部分は実例から直す。Thinkingやモデルを一律に変えることを今回の解決策にはしない。

## 5. 実施範囲

本書の実行では、公開情報の実検索・閲覧・取得、研究用の補助コード・保存領域・Skillの変更、必要な研究用プロファイルでのHermes試用を認める。v3から検索用の馬名・出走情報を得るため、正規の読み取り専用参照または既存エクスポートを利用し、NLP側の研究領域へ候補ファイルを作成してよい。既存の稼働DBと読取処理の競合を避ける正規手順を使う。通常の調査先や手順の変更ごとに確認を求めない。

研究範囲の候補群について、一覧の複数ページを辿る、複数馬を連続して検索する、記事本文をまとめて保存する作業は本研究に含む。調査量・実行時間・取得間隔は媒体の制約と実測に合わせて判断する。全10年・全馬の無期限処理や定期運用の開始は今回の完了条件にせず、必要な規模と次の作業を提案する。

v3のDB・コード・購入処理・稼働サービスや通常NLP DBを変更せず、既存データ・通常プロファイルを保全する。恒久サービス、定期実行、双方向同期、全旧データの移行は別作業である。実機や名簿に正規にアクセスできない場合も、利用可能な公開名簿や出馬表で研究を進め、未実施箇所を具体的に残す。

アクセス方針・認証・有料壁・レート制限は共通規約に従う。取得経路が対応していないことと、サイトがアクセスを拒否していることを混同しない。本文・大量の収集データ・生ログ・資格情報は公開Gitへ入れず、既存の許容されたGit外保存先へ残す。

## 6. 評価と成果物

今回示すのは、**どの入口をどう使うと新しい記事が増え、次回もその続きを進められるか**である。精密な意味正解率、全頭の記事存在証明、全媒体の網羅、全件の目視検査は要求しない。

終了時には、実際に辿った媒体の経路、日常の馬名一覧の入手と使い方、過去の馬名からの発掘を説明し、本文のまとまった保存と再開の方法を残す。3場面で一例ずつ成功したことや、3つのSkill・3人の子の完了だけで「検索研究完了」としない。量が増えない方法も、その実測と切替・改善方針を研究結果として扱う。

主な成果物は次のとおり。大きな管理台帳は作らず、次の担当が使える内容を優先する。

1. **実施レポート**：`docs/reports/YYYY-MM/YYYY-MM-DD_nlp_collection_routes_horse_seeds_report.md`。日常の事前・事後・過去を分け、辿った入口と操作、対象馬・期間、候補URLと保存した異なるURLの件数、発見・取得・解釈に使った時間の大まかな内訳、増えた範囲、未探索・取得困難・次に進める方向を記す。容易に得られる集計を使い、正確な時間追跡基盤は不要。
2. **更新したSkillと媒体別の実践知**：入口URL、一覧・検索・ページ送り等の使い方、馬名や活動時期との組合せ、再訪方法、確認した取得経路、適用範囲を残す。試した方法と未試行の案を区別する。
3. **必要な補助コードと再開情報**：名簿の取得元・期間、研究用データの保存先、既知URL・未解釈記事・続きの位置が分かるようにする。巨大な証拠台帳やDBの完成版設計は不要。
4. **Hermesへの引き渡し結果**：どの方法を実際に試せたか、足りない機能と小さな変更を示す。研究に使った経路とHermesで再現した経路の違いを隠さない。

開始時に最新 `origin/main` を確認し、成果物の対象ファイルのみcommit・pushして反映を確認する。本書自体の追加は研究の実行完了を意味しない。

### 次の担当へ渡す方針

> Codex自身が、競馬記事の一覧・特集・サイト内検索・ページ送りと、登録馬・出走馬・過去の出走馬の名簿を使って、広く大量に集める方法を研究してください。馬名は日常運用でも過去記事でも探索の入口に使います。解釈は9割がた役立てば十分で、意味・日時・対象の完全性を収集条件にしません。本文保存を記事解釈の完了待ちにせず、記事が増えるところまで実際に探索・保存し、その方法をSkillにまとめてからHermesへ引き渡してください。
