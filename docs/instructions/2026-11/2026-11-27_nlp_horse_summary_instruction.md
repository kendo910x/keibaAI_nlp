# 馬別の解釈一覧と、1記事・1頭の要約への修正

2026-11-27のユーザー指示に基づく実装。基準版は `f91ea411b70f4b574e626c8bc26b77b769ff4224`。

## 目的と出力単位

馬名から、その馬について保存済みの解釈文を直接読めるようにする。解釈は **1記事（本文版）につき、同じ馬を一つの要約にまとめる**。同じ馬を文、発言、競走、事前・事後ごとに分割しない。複数の競走や過去走が出る場合も、一つの文章の中で関係が分かるように書く。複数段落は使ってよい。

記事の意味は従来どおり概ね役に立てばよい。全件の意味検査、厳密な馬ID照合、カバー率調査は追加しない。話者、留保、否定、食い違い、過去走が今回の評価を支える関係は自然文に残す。

## 実装

1. 閲覧専用Dashboardに馬別の解釈検索を追加する。見出しだけでなく対象馬の解釈文、記事の日付、出典、保存原文へのリンクを表示する。検索時にLLMを起動しない。
2. 最新の本文版に対する最新の成功解釈を選んでから馬名を検索し、1記事・1頭を一つの表示単位にする。既存の分割済み解釈は原記録を変更せず、一つのカード内に従来の文章として表示する。新たなLLM要約を作ったように表示しない。
3. 原文を探す入口と、未解釈の関連記事への入口を残す。解釈がまだない場合に、原資料も存在しないと誤認させない。
4. `keiba-interpret` を簡潔な馬別要約の指示へ修正する。既存の `horse`、`race`、`phase`、`text` を保ち、`race` と `phase` は主な対象の補助情報とする。分割後に追加LLMで再統合する工程は作らない。
5. Skill変更だけで全ての成功済み記事が自動的に再解釈対象へ戻る挙動を止める。明示的に指定した保存記事の再解釈と、未処理記事の通常処理は維持する。

## 検証と実機への反映

今回の実装環境からVM15へのTCP接続は `Network is unreachable` であり、実機配備・実データの再解釈・Local LLMの時間計測はここでは実行できない。コードとSkillを公開し、この制約と残作業を実施報告に明記する。実機の反映済みとは報告しない。

手元では、馬をまたいだ文章混入、過去の成功結果の検索混入、同じ馬の複数競走を複数カードへ分ける挙動、文字列のエスケープ、記事一覧への戻り先を重点的に確認する。通常のコード検証を自然言語の全件正解検査へ広げない。

実機で次に行う有限確認は、検証用DBの保存済み記事からカランダガンのデイリー記事など少数を選び、同じ入力・モデル設定で新Skillの結果を生成する。旧結果と新結果の所要秒、思考・回答トークン、同一馬の出力件数、読みやすさを比べる。通常会話に近い短い馬別要約依頼を比較する場合は、その要求・結果を検証領域にだけ残す。現在の3～4分という観測だけを理由にモデル、Thinking、出力上限を弱めない。今回のコード変更ではこれらの設定を維持する。

本番DBの空状態と運用開始待ちは維持する。新たな収集、全名簿の初期構築、毎朝Cronの登録、全件再解釈は今回の範囲に含めない。起動中の検証処理を中断する場合は進捗を保ち、保存済み資料を失わない手順で配備する。
