# 開発PCでの日本語Embedding実行環境 PoC 指示書

作成日: 2026-11-22 / 対象: `keibaAI_nlp`

## 目的・実行前提
開発PC上で、競馬の日本語コメントを**学習済みEmbeddingモデルでベクトル化し、自然言語による類似検索を実行**できることを確認する。最初に `AGENTS.md` を読む。本タスクはG1記事探索の成否に依存しない。EVO-X2／Halogenで別モデルを起動しない。

## 実施範囲
1. 開発PCのOS、既存Python・CPU・メモリと、既存環境を汚さず利用できるPython仮想環境を確認する。管理者権限が必要な環境変更や、既存のv3環境へのパッケージ追加は行わない。
2. まず `Qwen/Qwen3-Embedding-0.6B` を候補に、**CPUのみ**で短文のEmbeddingを生成する。モデル・ライブラリは取得元、revision、バージョンを記録し、ローカルに取得したWeightはGit管理しない。必要なライブラリは独立した仮想環境へ導入する。
3. 競馬コメントを模した日本語サンプル（少なくとも12件、肯定・否定・距離延長／短縮・馬場適性の対照を含む）についてベクトルを作り、次元数、型、空ベクトルやNaNの有無を確認する。
4. 検索文を同モデルでEmbeddingし、cosine類似度で上位5件の**原文とスコア**を表示する小さな再現可能スクリプトを作る。必要ならモデル推奨のquery／document用入力形式を使う。
5. G1記事探索の結果 `data/poc/g1_passages.jsonl` が利用できる場合はその `text` でも試せるようにする。ただし同ファイルが存在しなくてもサンプルのみで完了できるようにする。

## 検証・境界
- CPU実行時のモデルロード時間、Embedding所要時間、ピークメモリの実測または計測可能範囲、検索結果（特に延長／短縮や否定の混同）を報告する。期待通りの検索になると前提しない。
- CPUで実行できない／著しく重い場合は原因と測定値を報告し、代替小型モデルやGPU使用は**無断で採用しない**。
- 専用サーバー、DB、常駐ワーカー、コンテナ、学習／Fine-tuning、v3改修は対象外。取得記事・Embedding・モデルWeight・一時ログはGit管理しない。
- 使い方をREADMEまたは短い実行手順にまとめ、再実行可能な最小スクリプト・必要な依存定義だけtracked fileにする。再利用に必要な量を超えてframework化しない。

## 完了・報告
サンプルのベクトル化と検索が実行でき、結果を人間が確認できること。どの表現を取り違えるかも含め、`docs/reports/2026-11/2026-11-22_embedding_cpu_environment_poc_report.md` に実測と未確認事項を記録する。対象fileだけcommit／pushし、以後の記事データを投入するのに必要な次の一手を提案する。
